# AI Workforce — ユーザーマニュアル

> 言語: **日本語** · [Bản tiếng Việt](USER_MANUAL_VI.md)  
> 更新日: 2026年8月27日

## 1. はじめに

AI Workforce は、複数の専門 AI エージェントと業務管理機能を統合した企業向けプラットフォームです。業務の振り分け、社内文書の検索、タスク管理、人による承認、AI コスト管理、監査ログなどを利用できます。

本書は、一般ユーザー、マネージャー、管理者向けの操作ガイドです。技術者向けのセットアップ手順については、[プロジェクト README](../../README.md) を参照してください。

## 2. クイックスタート

### 2.1 システムにアクセスする

1. 管理者から案内された URL を開きます。ローカル環境の既定 URL は <http://localhost:3000> です。
2. **ログイン**画面でメールアドレスとパスワードを入力し、**ログイン**を選択します。
3. ログインに成功すると、**CEO ダッシュボード**が表示されます。

組織がまだ作成されていない場合は、登録画面から**新しい組織を作成**できます。組織を作成したアカウントには `Owner` ロールが付与されます。企業環境では、管理者が組織とユーザーアカウントを作成する運用を推奨します。

### 2.2 表示言語を切り替える

左サイドバー上部で次のいずれかを選択します。

- `JA`: 日本語表示
- `VI`: ベトナム語表示

選択した言語は現在のブラウザーに保存されます。ユーザーが入力した内容や一部の業務データは、元の言語のまま表示されることがあります。

### 2.3 ログアウトする

左サイドバー下部の**ログアウト**を選択します。共有端末を利用した後は、必ずログアウトしてください。

## 3. ロールとアクセス権

実際の権限は、所属部門、各 AI エージェントに割り当てられたツール、および組織のポリシーによっても制限されます。

| ロール | 一般的な利用範囲 |
| --- | --- |
| `Owner` | ワークスペース全体の管理、メンバー、設定、エージェント、データライフサイクルの管理。 |
| `Admin` | ユーザー、エージェント、外部連携、および運用設定の管理。 |
| `CEO` | 全体状況の確認、エージェントの統括、承認、エージェント設定。 |
| `Manager` | 許可された範囲内での業務およびデータ管理。 |
| `Employee` | 許可された AI エージェントと業務機能の利用。 |
| `Guest` | ワークスペース設定に応じた制限付きアクセス。 |

権限がない機能は、読み取り専用、非表示、またはアクセス拒否になる場合があります。監査履歴を正しく残すため、アカウントを共有しないでください。

## 5. AI エージェントを利用する

### 5.1 適切なエージェントを選ぶ

左サイドバーの**AI エージェント**を展開し、目的に合うエージェントを選択します。

| エージェント | 主な用途 |
| --- | --- |
| CEO | 複数部門にまたがる複雑な依頼の計画と調整。 |
| HR | 人事規程、休暇残日数、休暇申請、オンボーディング、従業員情報。 |
| Legal | 契約書レビュー、版比較、機密データ確認、法務文書の下書き。 |
| IT | 技術情報の検索、サポート依頼の作成。 |
| Finance | 請求書と PO の照合、許可された財務業務。 |
| Sales | 営業情報の検索、見積書の作成。 |
| Knowledge | 出典付きの社内文書検索と質問回答。 |

エージェント横の緑色の点は稼働中を示します。それ以外の状態では、一時的に利用できない可能性があります。

### 5.2 わかりやすい依頼を作成する

1. 目的、対象範囲、期限を明確にします。
2. 許可されている場合は、社員番号、契約番号、PO 番号、関連文書を指定します。
3. 「5項目で要約」「表形式」「金曜日までのタスクを作成」など、希望する出力形式を伝えます。
4. 回答、出典、アクションカードを確認してから次に進みます。

例:

```text
私の有給休暇の残日数を確認し、9月5日から6日までの休暇申請を作成してください。
理由は家族の事情です。私が確認するまでは申請を送信しないでください。
```

```text
最新版の出張旅費規程を検索し、宿泊費と交通費の上限を要約してください。
参照した文書名と該当箇所も示してください。
```

### 5.3 承認が必要な操作

データの書き込み、外部サービスへの送信、またはリスクのある操作では、承認依頼が作成される場合があります。

1. 内容、依頼者、リスクレベル、入力データを確認します。
2. プレビューや添付文書がある場合は開いて確認します。
3. 必要に応じてコメントを入力します。
4. **承認**または**却下**を選択します。

AI の要約だけを見て承認しないでください。最終内容の確認責任は承認者にあります。

## 6. ナレッジベースを管理する

### 6.1 文書をアップロードする

1. **ナレッジベース（RAG）** → **新規作成**を開きます。
2. ファイルを選択します。画面で対応している形式は `.pdf`、`.docx`、`.txt`、`.md`、`.csv` です。
3. コレクション名を入力し、部門別の**アクセス範囲**を選択します。
4. チャンク方式を選択します。
   - **標準チャンク**: 比較的独立した段落で構成される文書向け。
   - **親子チャンク**: 広い文脈を保持する必要がある長文向け。
5. 必要に応じてチャンクサイズとオーバーラップを調整し、**チャンクをプレビュー**します。
6. 内容を確認してインデックス作成に進みます。
7. `アップロード → 解析 → チャンク分割 → Embedding → インデックス作成` が完了するまで待ちます。

重複した内容が検出された場合は、文書の版を確認してから**旧版を保持**または**置換して処理**を選択します。

### 6.2 文書を確認する

文書一覧から対象を開くと、処理状態、チャンク設定、インデックス済みチャンクを確認できます。検索欄で特定の内容を確認できます。安定した RAG 結果を得るには、状態が **完了 / Ready** の文書を使用してください。

### 6.3 データ取り扱いルール

- 適切な部門を選択してください。範囲が広すぎると、社内情報が不要なユーザーに見える可能性があります。
- パスワード、API キー、シークレット、不要な個人情報をアップロードしないでください。
- 文書をアップロードする前に、著作権と利用権限を確認してください。
- 文書を削除すると関連チャンクも削除され、復元できない場合があります。

## 7. タスクを管理する

1. **タスク管理（Kanban）**を開きます。
2. タスクを作成し、タイトル、説明、優先度、期限を入力します。
3. 従業員または適切な AI エージェントに割り当てます。
4. `DRAFT`、`PENDING`、`RUNNING`、`WAITING_APPROVAL`、`COMPLETED` などの状態で進捗を確認します。
5. カードをドラッグするか、一覧から状態を選択します。許可された状態遷移のみ実行できます。
6. タスク詳細を開き、履歴の確認やコメントの追加を行います。

直接削除できるのは `DRAFT` または `COMPLETED` のタスクです。処理中のタスクは、ワークフローで許可されている場合に `CANCELLED` へ変更してください。

## 8. カレンダー、通知、ワークフロー

- **業務カレンダー:** 権限範囲内で予定、タスク期限、人事イベントを作成・確認します。
- **通知:** ベルアイコンで概要を確認し、`/notifications` で全件表示や既読処理を行います。
- **ワークフロー:** 複数ステップの進捗、担当エージェント、承認待ち状態を確認します。失敗したステップは、エラーを確認してから再試行または担当者へ割り当てます。

## 9. 承認センター

1. **承認センター**を開きます。
2. 承認待ち一覧から対象を選択します。
3. 操作種別、リスクレベル、依頼者、入力データ、プレビューを確認します。
4. 監査証跡としてわかりやすいコメントを追加します。
5. 情報が十分な場合のみ承認します。却下する場合は、理由と修正方法を記載します。

処理済みの項目が残っている場合はページを更新してください。想定した依頼が表示されない場合は、承認者のロール、部門、ワークフロー状態を確認します。

## 10. 管理者向け機能

### 10.1 従業員と権限

`Owner`、`Admin`、`CEO` は次の操作を実行できます。

- 初期パスワードが8文字以上の従業員アカウントを作成する。
- ロールと部門を割り当てる。
- アカウントを有効化または無効化する。
- ユーザー一覧を検索・絞り込みする。

`Owner` アカウントの一部の保護属性は変更できません。必要最小限の権限を付与し、通常業務には管理者アカウントを使用しないでください。

### 10.2 AI 従業員設定

**AI 従業員設定**では、権限を持つユーザーがエージェントの有効/無効、システムプロンプト、モデル、ツール、アクション、ナレッジ範囲を設定できます。変更後は次の手順で確認します。

1. 権限一覧を再確認します。
2. 設定を保存します。
3. 破壊的でないテスト依頼を実行します。
4. 監査ログを確認します。

不要な書き込みツールや外部連携をエージェントに付与しないでください。

### 10.3 企業連携

接続を作成するときは、プロバイダーを選択し、セキュリティ運用に従って認証情報の参照を設定し、利用を許可する `agent roles` を明示します。エージェント一覧が空の場合、その接続はどのエージェントにも許可されていません。

認証情報や API キーをチャットに入力しないでください。システム用キーは、運用手順に従って環境変数またはシークレット保管庫で管理します。

### 10.4 AI コストと予算

**AI コスト管理**で、全体およびエージェント、従業員、部門、ワークフロー別の利用状況を確認します。画面で許可されている場合、管理者は予算上限やモデルルーティングルールを設定できます。コストが急増した場合は、リクエスト数、モデル、トークン数、繰り返し実行されたワークフローを確認してください。

### 10.5 会社設定とデータ

**会社設定**では、会社名、ロゴ、タイムゾーン、言語、既定モデル、データ保持期間、セッションタイムアウト、許可メールドメイン、IP 許可リストを管理できます。

- **JSON エクスポート**には、パスワードハッシュと認証情報の参照は含まれません。
- ワークスペース削除依頼には `Owner` 権限、正確なドメイン、理由が必要です。送信時点では削除されず、レビュー待ちの依頼として記録されます。

## 11. 監査ログ

**監査ログ**では、誰が、いつ、どの操作を実行したか、関連するエージェント、変更前後の値を追跡できます。問題調査時は次の手順を使用します。

1. 発生時刻付近に絞り込みます。
2. ユーザー、エージェント、操作種別でさらに絞り込みます。
3. 関連するタスク、ワークフロー、承認と照合します。
4. 許可なくログを変更したり、外部へ共有したりしないでください。

## 12. セキュリティと責任ある AI 利用

- AI の回答は確認が必要な提案であり、最終判断ではありません。
- パスワード、トークン、API キー、業務範囲外のデータを入力しないでください。
- 出典を確認し、不十分または不適切な場合は再検索を依頼してください。
- 契約書、見積書、メール、外部操作は、承認前に必ずプレビューしてください。
- 自分の部門や権限範囲外のデータが表示された場合は、管理者に報告してください。
- 共有端末では画面をロックし、利用後にログアウトしてください。

## 13. トラブルシューティング

| 症状 | 対処方法 |
| --- | --- |
| ログインできない | メールアドレス、パスワード、ネットワーク、アカウント状態を確認します。無効化されている場合は管理者に連絡します。 |
| 読み込みが終わらない、通信エラーになる | 一度だけ再読み込みし、管理者に Backend / AI Service の状態確認を依頼します。書き込み操作を繰り返し送信しないでください。 |
| エージェントが表示されない、ツールを使えない | エージェントの有効状態、ロール、部門、ツールおよびナレッジ権限を確認します。 |
| 回答に出典がない | Knowledge エージェントを使用し、明確な出典を求めます。文書が `Ready` であることも確認します。 |
| 文書処理に失敗する | 詳細画面でエラー、形式、サイズを確認して**再試行**します。重複文書を何度もアップロードしないでください。 |
| タスク状態を変更できない | システムが許可する次の状態を選び、承認待ちでないか確認します。 |
| 承認依頼が表示されない | 承認者の権限、部門、ワークフロー状態を確認し、一覧を更新します。 |
| 言語が完全に切り替わらない | ページを更新します。ユーザー入力や一部の業務データは自動翻訳されません。 |

不具合を報告するときは、発生時刻、画面名、直前の操作、エラーメッセージ、該当するタスクまたはワークフロー ID を管理者へ伝えてください。シークレットや機密情報を含む画像は送らないでください。

## 14. 推奨利用フロー

```text
適切なエージェントを選ぶ → 依頼を明確に書く → 回答と出典を確認する
→ 操作をプレビューする → 必要に応じて承認する → タスク/ワークフローを追跡する
→ 通知と監査ログを確認する
```
